# Game Mode HUD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Beta Features section, "Game Mode", that puts a thin readout strip over a fullscreen game showing CPU and GPU temperature and usage, RAM %, and battery charge and drain, for as long as a game is the frontmost app.

**Architecture:** Pure rules in PowerKit decide "is this app a game", format the strip's text from `MetricRegistry` values, and place the strip on a screen. An AnodeApp controller takes the frontmost app, the registry reader and a presenter as injected dependencies, shows or hides the strip, and tells the sampler which readings it needs only while the strip is up. The strip is one borderless, click-through window per the verified overlay recipe below. The existing tick feeds it; it has no timer of its own.

**Tech Stack:** Swift 5.9, AppKit, `MetricRegistry` (existing), XCTest (`Tests/PowerKitTests`).

**Spec:** the owner's brief of 2026-11-09 (in conversation; no separate spec file): "Temps and %'s for c/gpu, ram, and drain/current % (not EtD)… FPS if possible", "this should be the whole time, if the user doesn't want it they can turn it off in beta features menu", "top right (maybe customizable in the BF menu too), thin strip", "any app in macOS's Games category is a game, with a way to add others by hand" (yes). The decisions this plan adds are marked *(author's call)*.

## Global Constraints

- Beta Features section titled "Game Mode". Setting `gameHUDEnabled` default **false**. **Off means nothing exists**: no observer, no window, no sampler need.
- Shown **only while a game is the frontmost app** *(author's call: a game left open in the background must not leave a strip over everything else)*. A game is an app whose bundle's `LSApplicationCategoryType` contains `games` (matches `public.app-category.games` and `…simulation-games`; verified on this Mac for Bloons TD6, Euro3v3, Plague Inc, SimplePlanes 2, Lunar Client), or whose bundle id is in the setting `gameHUDExtraApps`.
- Readings, in this order, from `MetricRegistry.shared.value(for:)`: `.cpuTemperature`, `.cpuUsage`, `.gpuTemperature`, `.gpuUsage`, `.memoryUsage`, `.batteryPercent`, `.batteryDrain`. **Not** `.batteryTimeLeft` (owner: games swing it wildly). A missing reading shows `—`, never `0`.
- Strip: thin, 22 pt high, text 11 pt monospaced-digit system font, white on `NSColor.black` at alpha 0.6, corner radius 6, no shadow. Corner setting `gameHUDCorner` ∈ `topRight` (default), `topLeft`, `bottomRight`, `bottomLeft`; margin 8 pt.
- Overlay recipe, **verified over Bloons TD6 fullscreen on 2026-11-09**: `NSWindow` borderless, `level = .screenSaver`, `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary, .stationary, .ignoresCycle]`, `ignoresMouseEvents = true`, `hasShadow = false`, shown with `orderFrontRegardless()` (never `makeKey…`: it must not take focus from the game).
- On a notched screen in fullscreen the strip sits **inside the black band at the top** (`screen.safeAreaInsets.top`, 39 pt measured here), so it covers none of the game. Fullscreen without a notch: at the very top edge. Not fullscreen: just below the menu bar. *(author's call; the band geometry was measured, the placement is to be confirmed in Task 5.)*
- Sampling stays cheap (`betterstats-must-be-lightweight`): while the strip is up the tick runs at the user's sample interval, not the 8 s hidden interval, and asks for `[.cpu, .memory, .gpu, .sensors]`; the moment it is down both revert. No second timer.
- FPS is **out of scope** (separate spike afterwards). Pausing wallpapers and "close this app" suggestions are out of scope.
- Package target stays macOS 13; no new dependency. Work on branch `game-mode` (from `live-wallpapers`); never commit to `main`. Stage files by name; `.vscode/launch.json` is modified by the editor and is never committed. Test command: `swift test --filter <TestClass>`.
- Automated tests never show a real window or read the real frontmost app. The real thing is exercised only in Task 5.
- After the last task, `./build-app.sh`, confirm `BSSourceCommit` in `~/Applications/Anode.app/Contents/Info.plist` equals `git rev-parse --short HEAD` and the running process's inode matches the installed binary (standing instruction: rebuild after every change).

## Review Focus

- The game quits, loses focus or is replaced by another app while the strip is up: the strip is gone and the sampler needs are empty again on the next evaluation. (Task 3)
- The feature is switched off while the strip is up: it hides at once and every observer is removed. (Task 3)
- A frontmost app with no bundle id, no readable `Info.plist` or no category: treated as "not a game", no crash. (Tasks 1, 3)
- A reading is missing (no sensor on this Mac, on AC so no drain): `—` in its place, and the other readings still show. (Task 2)
- Secondary display with a non-zero origin, notch and non-notch screens, all four corners: the strip's frame is always fully inside the screen. (Task 2)
