# Lid Glass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Beta Features toggle, off by default, that frosts the built-in display like glass as the MacBook lid closes (driven by the real lid angle) and clears the frost after the next unlock.

**Architecture:** Pure logic (settings, report parsing, poll policy, close detection, spring, blur curve) lives in PowerKit and is unit-tested. The AppKit side is a controller that takes its sensor, capture, overlay and clock as injected dependencies so the whole state machine is tested with fakes; the real parts are an IOKit HID reader, a ScreenCaptureKit one-shot, and a borderless overlay window drawn by a Metal shader that is compiled from a source string at run time (the package builds with `swift build`, which does not produce a `.metallib`).

**Tech Stack:** Swift 5.9, AppKit, Metal/MetalKit, ScreenCaptureKit (macOS 14+), IOKit HID, XCTest (`Tests/PowerKitTests`).

**Spec:** `docs/superpowers/specs/2026-11-03-lid-glass-design.md`

## Global Constraints

- Beta Features section, **off by default**; while off, nothing runs: no polling, timers, capture or windows.
- Idle polling rate is a slider, **4–30 Hz** (default 8 Hz); polling goes to **120 Hz** from the trigger until the effect ends; sustained reads over **8 ms** drop it to **60 Hz**.
- Trigger angle is adjustable: range 60–150°, default 110° (the author's call, not owner-decided).
- **No shader sliders.** No private APIs (no SkyLight). Built-in display only; no effect while an external display is attached.
- Sensor: HID vendor `0x05AC`, product `0x8104`, usage page `0x20`, usage `0x8A`; feature report ID 1; three bytes: ID, then whole degrees little-endian. Reads never run on the main thread and never queue behind a hung read.
- Feature needs macOS 14+ (package target is 13, so gate with `#available(macOS 14.0, *)`); on 13 the toggle is disabled with "needs macOS 14 or later". Reuse `ScreenRecordingAccess` and its status text/button style (see `DockPreviewFeature`).
- Capture at the trigger by default; prewarm only if Task 9's measurement requires it (then gated on downward motion).
- The effect arms only on a downward move **through** the trigger with real speed; a lid resting below the trigger never starts it.
- The opening effect plays only on the first unlock (`com.apple.screenIsUnlocked`) after a lid close the closing effect saw; any key or mouse input cancels it; clear duration ≈ 0.5 s (author's call).
- Work on a new branch `lid-glass` off `main`; never commit to `main`. Commit steps below apply once the owner has asked for commits in the session. Test command: `swift test --filter <TestClass>`.
- The owner is using the Mac: no tests may close the lid, show a full-screen window, or prompt for permissions. Hardware-dependent steps are in Task 9 and are run only when the owner says so.

## Review Focus

- The lid resting below the trigger angle (people work at 100–120°): no effect ever starts. (Task 3)
- The lid reopens mid-close: overlay removed, polling back to the idle rate. (Task 7)
- Sensor absent, read fails, or stops responding mid-session: no crash, no stacked reads, the feature turns itself off and says so. (Tasks 2, 7)
- Display added/removed, external display attached, or the Mac sleeps while the effect is active: overlay removed, nothing left on screen. (Task 7)
- Toggle turned off, or Screen Recording revoked, mid-effect: everything torn down; an overlay without a picture is never shown. (Task 7)

### Task 2: Lid angle sensor and poll policy

**Files:**
- Create: `Sources/PowerKit/LidAngleSensor.swift`
- Test: `Tests/PowerKitTests/LidSensorTests.swift`

**Interfaces:**
- Produces:
  - `public enum LidAngleReport { public static func degrees(from bytes: [UInt8], length: Int) -> Int? }` — `nil` unless `length >= 3`, `bytes[0] == 1`, and the little-endian value (`bytes[1] | bytes[2] << 8`) is 0...360.
  - `public protocol LidAngleSource: AnyObject { var isAvailable: Bool { get }; func start(hz: Double, onSample: @escaping (Double, TimeInterval) -> Void, onLost: @escaping () -> Void); func setRate(hz: Double); func stop() }` — `onSample` gives degrees and a monotonic time in seconds, always called on the source's own queue, never the main thread.
  - `public final class LidAngleSensor: LidAngleSource` — the real HID reader; `init()`.
  - `public struct LidPollPolicy { public static let activeHz = 120.0; public static let degradedHz = 60.0; public static let slowRead = 0.008; public static let slowReadsBeforeDegrading = 5; public static func idleHz(_ requested: Double) -> Double; public mutating func recordRead(seconds: Double) -> Double }` — `idleHz` clamps to 4...30; `recordRead` returns `degradedHz` after 5 consecutive reads over `slowRead`, resets to `activeHz` after any fast read.

  - `testIdleHzClamps`: `idleHz(2) == 4`, `idleHz(50) == 30`, `idleHz(8) == 8`.
  - `testSustainedSlowReadsDropTo60AndRecover`: four slow reads → `120`; the fifth → `60`; one fast read → `120`.
- [ ] **Step 2:** Run `swift test --filter LidSensorTests`. Expected: compile failure.
- [ ] **Step 3: Implement.** `LidAngleSensor`: match the HID device with the constants in Global Constraints through `IOHIDManager`; `isAvailable` is true when one device matches. ### Task 3: Close detection, spring, blur curve

**Files:**
- Create: `Sources/PowerKit/LidMotion.swift`
- Test: `Tests/PowerKitTests/LidMotionTests.swift`

**Interfaces:**
- Produces:
